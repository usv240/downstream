What the key is

One key, one private tenant

The tenant your key speaks for is minted by this server, never chosen by you. Two people who create keys minutes apart land in separate namespaces, so a workspace id belonging to one is a 404 for the other even if it is guessed correctly.

  • Only a SHA-256 digest of the key is persisted.
  • Seven-day lifetime, and DELETE /v1/key revokes instantly.
  • No credential is written to browser storage.
  • The public demo stays credential-free.

    Step 3 of 3

    API reference

    Everything the service exposes. The interactive OpenAPI schema is at /docs; /openapi.json is the machine-readable contract.

    Authentication

    Send your key in the X-API-Key header on every /v1 route. Public routes under /downstream and /health need no key at all.

    X-API-Key: ds_beta_your_key_here

    Errors

    • 401 missing, invalid, expired, or revoked key.
    • 403 the key lacks the required scope.
    • 404 no such workspace for your tenant. Another tenant's workspace is indistinguishable from one that does not exist.
    • 422 the request was understood but rejected: unknown question, already answered, empty answer, revision without a reason.
    • 429 a daily ceiling was reached. X-RateLimit-Reset tells you when it returns.
    • 503 a dependency is unavailable, such as the public NID service.

    Sized so thorough evaluation never hits a wall. Counters are Firestore transactions and reset at UTC midnight. What is stored is an HMAC of your address, never a raw IP.

    Boundary

    Drafting and screening support only. There is no endpoint that approves, certifies, or submits a plan, and none that produces an inundation extent, depth, velocity, arrival time, or evacuation zone. The executable proof asserts this on every deploy.

    Notes

    • The API starts from an authoritative public USACE NID record, not from dam facts you supply. Find a real identifier with GET /downstream/nid/search.
    • A null EAP_PREPARED means unreported in that public field. It is never evidence that no plan exists.
    • Owner answers are stored verbatim in your workspace. A pseudonymised form is what crosses any model boundary.
    • The demonstration dam, drawing, and answers are synthetic. No agency seal is used and the project is not affiliated with USACE, FEMA, ASDSO, or any state agency.

    Provisioning, rotation, and operator-managed keys are documented in the beta API guide.

    Downstream produces a reviewable draft for owner, emergency-manager, state dam-safety, and qualified engineering review. Nothing is certified, approved, or submitted.
